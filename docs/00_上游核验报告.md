# 00 · 上游与设备支持核验报告（A 项）

- 核验时间：2026-10-27（Asia/Shanghai）
- 核验方式：GitHub REST/raw（分支列表与文件内容）+ LineageOS wiki 页面（站点生成时间 2026-10-26）
- 核验人：GITHUB（记录可复现的仓库 + 分支 + commit SHA）
- 说明：**本次核验只读上游信息，没有 clone 全量源码，没有执行任何构建或刷机。**

## 1. 结论摘要

1. `polaris` 的**官方支持版本仍停在 LineageOS 22.2 / Android 15，内核 4.9**。
   Android 16（`lineage-23.2`）属于需要自行验证的实验性设备移植，说明书 §2.2 的提醒成立。
2. 设备树、公共设备树的 `lineage-23.2` 分支**存在但内容与 `lineage-22.2` 完全相同**（同一 commit），
   说明上游只是切了分支，尚未见到针对 Android 16 的设备适配提交。
3. **内核仓库没有 `lineage-23.2` 分支**（最高 `lineage-22.2`），**TheMuppets vendor blobs 也没有 23.2 分支**。
   这两项是当前 Android 16 路线的直接阻塞。
4. LineageOS 的 `breakfast`/roomservice 在内核依赖解析不到默认分支时会**直接退出**（见 §4），
   所以"直接在 23.2 上 breakfast"今天必然失败；必须显式锁定内核/blobs 版本或自建分支。
5. Termux 可用官方 release 预置：`v0.118.3`，arm64-v8a APK 为 Termux 官方 Debug 签名，
   必须 `presigned` 方式预置（不可重签）。启动组件为 `com.termux/.app.TermuxActivity`。

### 2.1 设备树实际内容核验（`lineage-23.2`）

- `lineage_polaris.mk`：继承 `device/xiaomi/polaris/device.mk` 与
  `vendor/lineage/config/common_full_phone.mk`，`PRODUCT_NAME := lineage_polaris`。
- `AndroidProducts.mk`：只注册 `$(LOCAL_DIR)/lineage_polaris.mk`。
- `device.mk`：继承 `vendor/xiaomi/polaris/polaris-vendor.mk` 与
  `device/xiaomi/sdm845-common/sdm845.mk`。
- `BoardConfig.mk`：`TARGET_KERNEL_CONFIG += vendor/xiaomi/polaris.config`，
  并 `include vendor/xiaomi/polaris/BoardConfigVendor.mk`。
- `lineage.dependencies`：只声明 `android_device_xiaomi_sdm845-common` → `device/xiaomi/sdm845-common`。
- `sdm845-common/lineage.dependencies`：声明 `android_hardware_xiaomi` 与
  `android_kernel_xiaomi_sdm845`（后者**无 branch 字段**，依赖 roomservice 分支回退）。
- 内核仓库 `lineage-22.2` 中 `arch/arm64/configs/vendor/xiaomi/polaris.config` 存在。
- vendor blobs：`polaris-vendor.mk`（21 KB）自带全部 blobs；`BoardConfigVendor.mk` 为空注释文件；
  但 `sdm845.mk` 继承 `vendor/xiaomi/sdm845-common/sdm845-common-vendor.mk`，
  所以 **polaris 与 sdm845-common 两个 blobs 仓库都需要**。

### 2.2 官方支持状态（wiki）

- 设备页 `https://wiki.lineageos.org/devices/polaris/`：当前版本 **22.2 (Android 15)**，内核 **4.9**。
- 构建页 `https://wiki.lineageos.org/devices/polaris/build/`：官方支持分支列表止于 `lineage-22.2`；
  推荐 `repo init -u https://github.com/LineageOS/android.git -b lineage-22.2`；
  硬件要求写着 lineage-21 起建议 64 GB RAM、400 GB 存储。

## 4. roomservice 行为（决定 local manifest 为何写死内核/blobs）

`vendor/lineage/build/tools/roomservice.py`（lineage-23.2）关键逻辑：

- 对每个 `lineage.dependencies` 项目调用 `is_in_manifest('project', 'path', target)`，
  该检查会扫描 **`.repo/local_manifests/*.xml` + 主 manifest + lineage snippet**。
  → 只要我们在 local manifest 里先声明该 path，roomservice 就不会再重复添加。
- 若 dependency 没有 `branch` 字段，则在 GitHub 上按当前默认分支查找，失败后用
  `ROOMSERVICE_BRANCHES` 环境变量里的候选分支回退；**仍失败则 `sys.exit(1)`**。
- 内核仓库没有 `lineage-23.2`，因此若不加干预，`breakfast polaris` 会在内核依赖处失败。

**决策**：在 `local_manifests/terminalos.xml` 里显式把内核与两个 blobs 仓库锁定到 `lineage-22.2`。
理由：可复现、不依赖环境变量；同时明确记录"这是 Android 16 实验路线的前提条件，不是官方支持"。
不把 `ROOMSERVICE_BRANCHES` 作为默认方案（结果依赖环境变量，不可复现），只作为文档中的备选说明。

## 6. 环境核验（本机）

| 项 | 实测值 | 结论 |
| --- | --- | --- |
| 操作系统 | Windows（非 Linux） | 不能直接做主构建机 |
| 内存 | 23.7 GB | 低于官方建议（21+ 建议 64 GB） |
| 逻辑核 | 16 | 可用但偏少 |
| 磁盘 | C: 约 1.7 TB 可用 | 空间够，但受 OS 限制 |
| WSL | **未安装** | 若要以本机为构建机，需先安装并验证 WSL2 磁盘/编译网络行为 |

结论：**需要一台独立 x86-64 Linux 构建机**（Ubuntu LTS 优先），见 `docs/02`。
