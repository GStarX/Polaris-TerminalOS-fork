## 2. 明确禁止事项（来自说明书 §9，逐条保留）

1. 未核验设备型号、固件、分区信息前，不刷写镜像。
2. 不禁用 `com.android.systemui`。
3. 不用 `wm overscan` 隐藏导航栏。
4. 不把 `settings put global policy_control immersive.full=...` 当终端锁定机制。
5. 未验证维护入口前，不开启永久锁定。
6. 自定义 ROM 未稳定前，不重新锁定 Bootloader。
7. 不混装不同签名来源的 Termux 与插件。
8. 不把 `lineage-23.2` 分支存在当作 Android 16 已获官方支持。
9. 自动启动脚本不得无限重启应用。
10. 不把用户数据写入只读系统镜像；初始化必须幂等。
11. 源码构建成功前，不同时引入大量 SystemUI / frameworks 修改。
12. 示例包名、组件名、分区名、刷写命令不得直接用于实机，必须以源码与设备检查结果为准。

## 3. 验收规则（适用于所有阶段）

1. **证据优先**：任何"通过"结论必须对应构建日志/命令输出/实机记录；没有记录视为未完成。
2. **不得代填**：其他角色不得替首席记录真机结果。
3. **两项独立**：Android 平台升级与 Linux 内核升级分开任务、分开提交、分开验收。
4. **可回滚**：每个功能提交必须写清回滚方式（`git revert <sha>` 或移除产品继承）。
5. **最小补丁面**：能用标准 Android API 解决的，不改 frameworks/SystemUI。
6. **构建可复现**：同源码 + 同构建机可重复产出，产物记录 sha256。
