## 1. 结论摘要（先看这里）

1. **本机（Windows 10/11，23.7 GB RAM，16 逻辑核，C 盘约 1.7 TB 可用，未安装 WSL）不适合作为主构建机。**
   需要一台独立的 **x86-64 Linux（Ubuntu LTS）** 构建主机。
2. **官方数字**：LineageOS **21+ 建议 64 GB RAM、400 GB 存储**（本机内存明显不足）。
3. **上游阻塞（已核实，不掩盖）**：`kernel/xiaomi/sdm845` 与 TheMuppets vendor blobs 均**没有 `lineage-23.2` 分支**，
   因此"纯上游状态直接构建 lineage-23.2"必然失败。项目用 [`local_manifests/terminalos.xml`](../local_manifests/terminalos.xml)
   把内核与 blobs **显式锁定 `lineage-22.2`**，作为**实验性**前提；这既不改变"23.2 无官方设备支持"的事实，
   也不代表 23.2 能编译或能启动（详见 [`docs/00`](./00_上游核验报告.md) §2/§4）。
4. **推荐路线**：先构建 **lineage-22.2 未修改基线**（证明构建链与设备可用），再做 **23.2 + 22.2 内核/blobs 实验构建**，
   逐项记录失败点。两条路线目前都**未执行**。
5. 官方设备页当前版本为 **22.2 / Android 15 / 内核 4.9**，官方支持分支截止 `lineage-22.2`；`lineage-23.2` 属于自行移植目标。

## 2. 上游事实与对构建的影响（2026-10-27 核实，来自 docs/00）

| 事实 | 结论 | 对构建的影响 |
| --- | --- | --- |
| `LineageOS/android` manifest 有 `lineage-23.2` 分支（仓库默认 `lineage-24.0`） | 23.2 源码树可以 `repo init` | 不是阻塞 |
| 设备树 `android_device_xiaomi_polaris` 有 `lineage-23.2`，SHA `1b46255c…`，与 22.2 相同 | 23.2 设备树只是从 22.2 切出，**无 Android 16 适配提交** | 23.2 设备行为未知，必须实机验证 |
| 内核 `android_kernel_xiaomi_sdm845` **没有** `lineage-23.2`，最高 `lineage-22.2`（SHA `aa8adfe9…`） | 23.2 内核依赖缺失 | **阻塞**（默认会构建失败） |
| TheMuppets vendor blobs（polaris / sdm845-common）**没有** `lineage-23.2` | 23.2 vendor 依赖缺失 | **阻塞** |
| 官方 wiki：polaris 当前 22.2 / Android 15、内核 4.9；构建文档支持分支截止 22.2 | 23.2 无官方支持 | 23.2 是实验路线 |
| `local_manifests/terminalos.xml` 已把内核与 blobs 锁定 `lineage-22.2`（docs/01 §3） | 23.2 的 `repo sync` 至少可以完成 | 依赖齐备 ≠ 能编译/能启动 |

> **口径要求**：任何时候不得把"23.2 分支存在"说成"Android 16 已获官方支持"，也不得把"sync 成功"当成"构建成功"。

## 3. 官方构建主机要求

依据 LineageOS 官方构建文档（[building_basics](https://wiki.lineageos.org/building_basics)）与 polaris 构建页
（[wiki: polaris/build](https://wiki.lineageos.org/devices/polaris/build/)）：

- **内存/存储**：LineageOS **21 起建议 64 GB RAM、400 GB 存储**（构建页对 polaris 也引用同一硬件要求）。
- **系统**：官方文档以 **x86-64 Ubuntu LTS** 为准（本项目建议 Ubuntu 22.04 / 24.04 LTS，具体以官方构建文档当前版本为准）。
- **说明**：官方数字是"完整构建的推荐值"，不是硬性最低值；低于该值可能极慢或 OOM，**本项目尚未实测**。

### 3.1 本项目建议配置（标注：推荐值来自官方，最低值为估算）

| 项目 | 最低（可能失败/极慢，未实测） | 推荐（按官方） | 说明 |
| --- | --- | --- | --- |
| 内存 | 32 GB + swap（**不保证**） | **64 GB** | 23.7 GB 的本机不在可接受范围 |
| CPU | 8 逻辑核 | 16+ 逻辑核 | 影响 `brunch` 并行与总耗时 |
| 磁盘 | 250 GB（**估算，可能不足**） | **400 GB+ SSD** | 源码 + `out/` + ccache 50 G + 产物 |
| 系统 | x86-64 Linux | **Ubuntu LTS x86-64** | macOS/Windows 非官方支持环境 |
| 网络 | 稳定宽带 | 稳定宽带/良好国际链路 | `repo sync` 需要下载数十 GB |
| 文件系统 | ext4（推荐） | ext4 | 不要用 NTFS/exFAT 存放源码（大小写、权限、符号链接问题） |

## 4. 本机现状核对

| 项 | 实测/已知值 | 相对要求 | 结论 |
| --- | --- | --- | --- |
| 操作系统 | Windows 10/11 | 官方要求 Ubuntu LTS | **不满足** |
| 内存 | **23.7 GB** | 官方建议 64 GB | **明显不足**（低于 32 GB 也低于 64 GB） |
| CPU | **16 逻辑核** | 建议 16+ | 基本够用 |
| 磁盘 | C 盘约 **1.7 TB 可用** | 建议 400 GB | 空间充足 |
| WSL | **未安装** | 非官方构建路径 | 不可直接当 Linux 构建机 |
| Git for Windows / bash | 已安装（可做脚本静态检查） | — | 仅用于编辑/校验，**不用于编译** |

**结论：本机不作为主构建机。** 本机可承担的角色：

- 编辑文档、脚本、产品配置（当前工作即在此进行）；
- 从构建机下载产物并做校验（sha256 复核）与归档；
- 作为文件缓存/中转（可选），不承担编译。

> 若将来考虑 WSL2：属于**未验证**方案，且 23.7 GB 内存仍低于官方建议；只能作为探索，不得作为默认构建路径。

## 5. 群晖 DS218+ 的定位

群晖 DS218+（按现有信息为双核、内存较小；具体规格以设备实际为准）**只适合**：

- repo 镜像/文件缓存（可选）；
- 文档与构建产物归档；
- 团队内文件共享。

**不适合**主力编译：CPU 核数、内存、存储 IO 与散热都不满足 Android 完整构建，且 DSM 环境不是官方构建环境。
不要在其上执行 `brunch`。

## 6. 推荐构建主机方案

| 方案 | 说明 | 优点 | 缺点/风险 | 当前状态 |
| --- | --- | --- | --- | --- |
| **A. 独立 Ubuntu LTS 虚拟机/物理机（首选）** | 64 GB RAM、400 GB+ SSD、x86-64 | 符合官方环境；可复现；与日常机隔离 | 需要额外硬件/虚拟化资源 | **未准备**（docs/03 P0-08 `todo`） |
| B. 云主机 | 按需租用 x86-64 Ubuntu 实例（大内存/大磁盘） | 无需自购硬件 | 成本、网络、数据合规、磁盘计费需评估 | 未评估 |
| C. 本机 WSL2 | 在 Windows 上装 WSL2 构建 | 无需新硬件 | 未安装、未验证；23.7 GB 内存不足；IO 性能风险 | **不推荐**作为主构建路径 |

**建议**：先落地方案 A。构建机与开发机分离；所有产物用 `sha256sum` 校验后回传归档（见 [`docs/05`](./05_构建与产物记录模板.md)）。

## 7. 依赖安装（脚本化）

依赖安装由 [`scripts/setup-build-host.sh`](../scripts/setup-build-host.sh) 完成，**不要手工零散执行**以免环境不一致。

### 7.1 用法

```bash
# 预检：只打印将要执行的命令，不修改系统（可在任意 Linux 机器上先看）
bash scripts/setup-build-host.sh --dry-run

# 正式安装：每条 sudo 命令都会先打印、再询问确认
bash scripts/setup-build-host.sh

# 非交互环境（例如已人工确认过命令列表）才用 --yes 跳过逐条确认
bash scripts/setup-build-host.sh --yes
```

### 7.2 脚本内容

1. **apt 依赖**（LineageOS 官方构建文档列表；脚本内为唯一维护点）：

   `bc bison build-essential ccache curl erofs-utils flex g++-multilib gcc-multilib git git-lfs gnupg gperf imagemagick kmod protobuf-compiler python3-protobuf lib32readline-dev lib32z1-dev libdw-dev libelf-dev libgnutls28-dev lz4 libsdl1.2-dev libssl-dev libxml2 libxml2-utils lzop pngcrush rsync schedtool squashfs-tools xsltproc xxd zip zlib1g-dev`

2. **ccache**：安装并设置上限 **50 G**（见 §8）。
3. **repo 工具**：下载到 `~/bin/repo`，并提示把 `~/bin` 加入 `PATH`（脚本不自动改 shell 配置）。
4. **git-lfs**：执行 `git lfs install`（Android 源码已使用 LFS，license 相关文件需要）。
5. **Change-Id**：`git config --global trailer.changeid.key "Change-Id"`（Gerrit trailer 规范）。

### 7.3 脚本安全特性（与 docs/04 §2 禁止事项一致）

- `set -euo pipefail`，失败立即停止并指出失败行；
- `--dry-run` 只打印、不执行；
- **不静默 sudo**：先 `echo` 完整命令，再请求确认；
- 幂等：已安装的包不重复安装，已存在的配置不重复写入；
- 非 Ubuntu 系只警告不硬退（但**只在 Ubuntu LTS 上受支持**）；
- 不下载 Android 源码、不构建、**不执行任何设备写入/刷机操作**。

> 当前状态：脚本已完成并通过 `bash -n` 静态检查与假环境 dry-run 自测；**尚未在真实 Ubuntu 构建主机上执行**。

## 8. ccache 设置

| 项 | 值 | 说明 |
| --- | --- | --- |
| 上限 | **50 G** | `ccache --max-size=50G`（脚本设置） |
| 默认目录 | `~/.ccache` | 计入磁盘规划（§9） |
| 作用 | 缓存 C/C++ 编译结果，重复构建大幅加速 | 首次构建无收益 |
| 观测 | 构建后记录命中率 | 写入构建记录（docs/05） |

注意：ccache 缓存与工具链版本相关；切换构建机/编译器后命中率会下降，属于正常现象。

## 9. 磁盘规划（估算，标注"参考"）

> 以下为**估算/参考**，本项目尚未实测实际占用；以构建机实测为准。

| 用途 | 估算占用 | 说明 |
| --- | --- | --- |
| 系统与工具 | 30–50 GB | Ubuntu + apt 依赖 |
| 源码树（`.repo` + 工作区） | 150–250 GB | `repo sync` 约数十 GB 下载、解压后更大 |
| `out/` | 80–150 GB | 单次构建产物与中间文件 |
| ccache | **50 GB** | 本项目固定 50 G |
| 产物归档 `out/artifacts/` | 20 GB+ | 保留多个版本时增长 |
| **合计建议** | **400 GB+** | 与官方建议一致；用 SSD |

建议：源码、`out/`、ccache 放在同一个大分区（ext4），不要跨文件系统；预留至少 15% 空闲空间。

## 10. 源码初始化与同步（脚本对应关系）

| 步骤 | 脚本 | 对应任务（docs/03） | 说明 |
| --- | --- | --- | --- |
| 构建机准备 | `scripts/setup-build-host.sh` | P0-08 / P1-01 | 装依赖、ccache、repo、git-lfs |
| 初始化源码 | `scripts/init-sources.sh` | P1-02 / P1-11 | 默认 `lineage-23.2` + local manifest；`--branch lineage-22.2 --no-local-manifest` 为纯上游基线 |
| 同步源码 | `scripts/sync-sources.sh` | P1-02 / P1-11 | 默认不加 `-j`；失败给降并发重试提示；同步后打印关键仓库 commit |
| 依赖检查 | `scripts/fetch-vendor-deps.sh` | P1-03 / P1-12 | 默认报告 23.2 内核/vendor 阻塞；`--allow-22.2-pinned-deps` 显式接受 22.2 锁定实验方案 |
| 基线构建 | `scripts/build-baseline.sh` | P1-04 | 只构建未修改 `lineage_polaris`；产物列表写 `out/baseline-artifacts.txt` |
| TerminalOS 构建 | `scripts/build-terminalos.sh` | P2-04 | `terminalos_polaris-userdebug`；Termux APK sha256 不匹配即失败 |
| 产物收集 | `scripts/collect-artifacts.sh` | P1-04 / P5-02 | 复制到 `out/artifacts/<时间戳>/`，生成 `sha256sums.txt` 与 `build-info.txt`，不覆盖历史目录 |

### 10.1 两条构建路线的环境差异

- **路线 1A（可执行基线）**：`repo init -b lineage-22.2`，**不加** local manifest（`--no-local-manifest`），
  使用上游设备树/内核/blobs。目的：先证明构建链与设备可用（docs/03 P1-01…P1-05）。
- **路线 1B（实验）**：`lineage-23.2` + local manifest（内核/blobs 锁 22.2）。
  目的：记录 23.2 的失败点（docs/03 P1-11…P1-13），**预期会失败，失败本身是交付物**。

### 10.2 构建命令（在源码根目录执行）

```bash
source build/envsetup.sh
breakfast polaris     # 或 bash scripts/build-baseline.sh 封装
brunch polaris
```

TerminalOS 产品使用 `lunch terminalos_polaris-userdebug` 后由 [`scripts/build-terminalos.sh`](../scripts/build-terminalos.sh) 执行
`brunch terminalos_polaris`。**这些命令只编译产物，不涉及任何设备写入**。
