# 21 · 系统应用精简：设备层流程与「重启回滚」根因（第 2 版，2026-11-01）

> 第 2 版定案：**不是**系统快照回滚、**不是**删除被恢复，而是**删除后立即重启，状态没落盘就被清掉**。
> 第 1 版的四条假说（H1 `/data` 不持久 / H2 换系统快照 / H5 只读挂载）已用设备证据排除，保留在 §4 作历史。
> 相关：候选清单 `_reviews/SLIM_CANDIDATES_C_O5.md`（v2）。

## 1. 根因（首席实测，已定位）

- 用户级移除状态记在 **`/data/system/users/0/package-restrictions.xml`**，**不是** `packages.xml`——盯着 `packages.xml` 的 mtime 会误判成"没写进去"。
- 用 `adb root`（userdebug，`id=uid=0`）执行 `pm uninstall --user 0` 后，restrictions 文件在约 10 秒内更新。
- **29 项全部回来**的真实原因：删完**立刻** `adb reboot`，状态尚未写入磁盘，重启把未落盘的改动丢了。
- 已排除：探针文件重启后仍在、`ro.build.fingerprint` 前后一致、`/data/system` 可写 → H1/H2/H5 均不成立。

## 2. 固定流程（必须逐条遵守）

1. `adb root`（确认 `id` 为 uid=0）。
2. 批量 `pm uninstall --user 0 <pkg>`，逐条看 `Success`。
3. **等 ≥10 秒**，确认 `/data/system/users/0/package-restrictions.xml` 的 mtime 已变化。
4. 重启抽验：`pm list packages --user 0` 查不到、`pm list packages -u -s` 仍能查到（镜像没动）。
5. 重启后再进下一批；**不许删完立刻重启**。

回退：`cmd package install-existing <pkg>`（一条命令恢复）；`glimpse` 要连它的 `org.lineageos.glimpse.frameworksbaseoverlay` 一起考虑。

## 3. 当前设备基线（2026-11-01，首席实测）

- `glimpse` 的 overlay 仍在（前后计数 2→1），镜像层 filter-out 时必须连 overlay 一起删。

## 5. 设备侧 root 的另外两条路（留给镜像层，不是现在）

- **systemless**（Magisk 模块 bind-mount 空目录盖 APK）：可逆、不动镜像、不碰 verity；OTA 后需重做。
- **直接 remount rw 删 APK**：仅当 `getprop ro.boot.veritymode` 确认关闭时安全，否则 bootloop；改动不可逆。

## 7. 实施计划与内存口径（2026-11-01 用户批准「都清、开始实施」）

### 7.1 批次顺序

| 批次 | 内容 | 方式 |
| --- | --- | --- |
| B3 | 功能类 6 项：`etar`、`twelve`、`recorder`、`deskclock`、`messaging`、`com.android.gallery3d` | 先 `pm disable-user` 观察一轮 → 正常再 `uninstall --user 0` |
| B4 | 主题 RRO：图标包 24 + 图标形状 7 + 字体 3（`blacktheme` 已在早批删除） | 整组一次；删前 `cmd overlay list` 留状态快照；删后启用一个再禁用 + 重启验证 |
| B5 | `Updater`（OTA 入口） | **默认保留**，等用户明确「不要 OTA」再动；删后只能线刷更新 |

每批前必做：**查该包是否提供 system service / action**（`AndroidManifest` service 声明）——`devicelockcontroller` 那次已证明「当前已禁用 ≠ 可删」。

### 7.2 每批放行门槛（沿用已定流程）

1. `adb root`；2. 批量删；3. 等 ≥12 s + `sync`；4. 确认 `package-restrictions.xml` mtime 变化；5. 重启；6. 验 `boot_completed=1`、HOME=`org.terminalos.terminalhome`、`LockTaskPolicy mFlags=7`、`locksettings get-disabled=true`；7. 采内存基线。

### 7.3 内存口径（三把尺子一起报，别混用）

静置 10 分钟后采：

```sh
grep -E 'MemTotal|MemAvailable|Cached|Buffers' /proc/meminfo      # (a) 系统口径
dumpsys meminfo | head -25                                          # (b) Android Used RAM
top -b -n1 -o RSS,NAME | head -20                                   # (c) 进程 RSS 排行
```

汇总时给三个数：
- **(a) `MemTotal - MemAvailable`**：含内核与可回收缓存，**不适合**当"Android 占用"；
- **(b) `dumpsys meminfo` Used RAM**：含 cached，仍偏大；
- **(c) Android 侧进程 RSS 之和（排除 Termux/Ubuntu）**：**800 MB 目标用这个口径判定**。

### 7.4 回退

`cmd package install-existing <pkg>`；RRO 用 `cmd overlay enable <name>`；若 bootloop，按 2026-11-01 已验证的恢复法：`adb root` → `stop` → 备份并删除 `/data/system/users/0/package-restrictions.xml` → `start` 重建，再补 `settings put global device_provisioned 1` / `secure user_setup_complete 1`、禁 SetupWizard、重启 TerminalHome。
