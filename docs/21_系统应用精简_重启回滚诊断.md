# 21 · 系统应用精简：设备层「重启后回滚」诊断（2026-11-01）

> 现象由首席实测上报；本文只给**可判别的假说与排除命令**，不下结论——设备侧证据未采齐前，机制算「未定」。
> 相关：候选清单 `_reviews/SLIM_CANDIDATES_C_O5.md`（v2）；镜像层路线见 TBD（待 vendor fork 落地）。

## 1. 现象（首席实测）

| 操作 | 当场 | 重启后 |
| --- | --- | --- |
| 首批 4 项用户级移除（camelot / calculator2 / blacktheme / glimpse 主包） | 查不到 | **3 项保持删除**，glimpse overlay 仍存在（2→1） |
| 第二批 29 项批量 `pm uninstall --user 0` | 全部 Success，224 → 195 | **29 项全部回来**，回到 224 |
| 单独复测 `com.android.egg` | 查不到 | **又回来** |

其它已排除项：`/data` 余 210 G、只有一个用户、DO 与锁任务重启后正常、logcat 缓冲区已滚过看不到 `pm_install`。

## 2. 假说与判别（按优先级）

**H1｜`/data` 的写入没进持久层（分区改造的副作用）**
该机 `/data` 挂在 `sda21` 且做过分区改造；若上层有 overlay/snapshot/tmpfs 合并，删除状态可能只落在临时层。
判别：
```sh
mount | grep -Ei ' /data|sda21|overlay|snapshot'
ls -l /data/system/packages.xml; ls -l /data/system/users/0/
dmesg | grep -iE 'snapshot|overlay|dm-verity|ext4.*recovery'
```

**H2｜重启后跑的不是同一个 system 快照**
若两次开机 `ro.build.fingerprint` / `ro.build.date` / `version.incremental` 不同，就是换了系统，而不是「删除被恢复」。
判别（重启前后各跑一次，逐项比对）：
```sh
getprop ro.build.fingerprint
getprop ro.build.date
getprop ro.build.version.incremental
getprop ro.boot.slot_suffix
cat /proc/cmdline
```

**H3｜存在恢复型机制把包装回来**
候选：DO/厂商策略、setupwizard 恢复、Magisk 模块的首次开机脚本、备份代理。
判别：
```sh
dumpsys device_policy | grep -iE 'install|package|suspend'
ls -l /data/adb/modules 2>/dev/null; magisk -v 2>/dev/null
logcat -b all -d | grep -iE 'pm_install|PackageManager.*(install|restore)|backup'
```

**H4｜删除状态写进了错的用户/配置**
判别：
```sh
dumpsys user | grep -E 'UserInfo|User 0|current'
dumpsys package com.android.egg | sed -n '/User 0/,+6p'
```

**H5｜写操作根本没落盘（只读挂载）**
判别：
```sh
mount | grep -E ' /data | /data/system '
touch /data/local/tmp/persist_probe && ls -l /data/local/tmp/persist_probe
# 重启后：ls /data/local/tmp/persist_probe（在=可持久，不在=H1/H5）
```

## 3. 设备侧 root 持久化两条路线（用户已授权 root，但仍不改 DO/锁任务）

**路线 A｜systemless（推荐先试）**：不动镜像，用 Magisk 模块 `bind-mount` 空目录/空文件覆盖目标 APK 路径；可撤销、可复用、不触发 verity。
- 优点：可逆、不影响 OTA 校验；缺点：依赖 Magisk 存活，OTA 后要重做。

**路线 B｜直接改只读分区**：`mount -o rw,remount` 后删 APK，**只有 verity 关闭（`getprop ro.boot.veritymode` = disabled，或 vbmeta 允许）才不会开机验证失败**。
- 优点：最接近最终镜像形态；缺点：一旦 verity 未关会 bootloop，且改的是镜像本体、难以回退。

**关键前提**：`pm uninstall --user 0` 按设计是持久的用户级状态，重启不该回来。**先按 §2 查清「为什么回来」，再谈 B 路线**——否则改成镜像也只是掩盖问题。
