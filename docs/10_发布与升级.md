# 10 · 发布与升级（Phase 5 设计）

> 状态：**规则与模板，未执行过任何发布**。

## 1. 版本号规则

采用 `terminalos-<android-major>-<yyyymmdd>-<git-short>`：

```
terminalos-16-20261101-1a2b3c4
   |        |        |
   |        |        └── 元仓库 Polaris-TerminalOS 构建时的 commit short sha
   |        └─────────── 构建日期（UTC）
   └──────────────────── Android 主版本（16 = lineage-23.2）
```

- 构建信息写入 `ro.terminalos.version`（见 `vendor/terminalos/terminalos.mk`，**未构建验证**）。
- 每个发布 tag 必须同时记录：四个仓库的 commit、lunch target、产物 sha256、构建机信息、实机测试编号。

## 2. 产物命名

沿用 LineageOS 规则，避免与官方包混淆：

```
lineage-23.2-<日期>-UNOFFICIAL-polaris.zip          # ROM 安装包
recovery.img                                        # Recovery
boot.img / dtbo.img（如由构建产出）                  # 内核相关镜像
sha256sums.txt                                      # 校验值
build-info.txt                                      # 构建信息
```

## 5. 升级路径

- **同类升级**（同 Android 版本内）：LineageOS Updater 走 OTA，需要签名一致与 ota 配置正确（**未验证**）。
- **跨版本升级**（22.2 → 23.2）：按 LineageOS 官方 "Upgrade to a higher version" 思路，需对应 firmware 要求；
  本项目的 23.2 属实验性，**不承诺提供跨版本升级路径**。
- **自定义 ROM 未稳定前**：禁止重新锁定 Bootloader（说明书 §9 第 6 条）。

## 6. 回滚原则

1. 保留与当前 ROM 构建对应的 boot/recovery 镜像与 sha256。
2. 大改（内核、锁定策略、精简）前先做已知可用版本的完整备份与回滚演练。
3. 回滚步骤必须写成可执行清单，并由首席在实机上至少演练一次。
