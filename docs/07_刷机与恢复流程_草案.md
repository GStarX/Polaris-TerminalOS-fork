# 07 · 刷机与恢复流程（草案）

> 文档状态：**草案 / 未执行 / 待验证**。本文**不提供任何可直接执行的刷机命令**，只写流程草案、前置条件核对清单、回滚与排障顺序。
> 所有步骤均标注"**待首席在 Phase 0 核实后补全**"；在补全并复核之前，任何一步都不得在真机上执行。
> 真机操作（解锁、刷入、恢复、重锁）**只由首席执行**；其他角色只准备材料、判据与记录模板（[`docs/04`](./04_风险与验收.md) §3）。

## 1. 当前状态与风险前提

1. **设备当前据称运行基于 `IOS_ON_MIX2S` 的 iOS 16 移植系统**——该说法来自说明书/转述，**未核实**。
   这意味着：设备的分区布局、引导链、Recovery、固件区域都可能与官方 Android 状态不同，
   **Android 的 adb/fastboot 行为不能假设可用**（[`docs/06`](./06_Phase0_设备核验清单.md)）。
2. **Phase 0 尚未完成**：Bootloader 状态、分区布局、Recovery 可用性、回退路径均未确认。
3. 因此：**在 Phase 0 全部核实并记录之前，禁止任何刷写、擦除、重锁、降级操作。**
4. 本文中的"流程"只是**待讨论的草案**，不是操作指令；任何命令、参数、文件选择都必须由首席在核实设备后另行确定并记录。

> **红线（任何情况下不得违反）**
> - 未核实设备型号/固件/分区前，不刷写任何镜像（docs/04 §2 第 1 条）。
> - 不在未确认回退路径的情况下开始刷写（没有"回到可启动状态"的方案就不动手）。
> - 不重新锁定 Bootloader（docs/04 §2 第 6 条）。
> - 不跨区域/跨固件版本混刷；不使用来源不明或校验值不明的镜像。
> - 真机操作只由首席执行；其他角色不得以任何方式代操作或"先试一下"。
> - 本文**不写入可直接复制执行的刷机命令**；正式步骤由首席补全在本文档后执行。

## 2. 前置条件核对清单（全部满足前不得进入刷写阶段）

### 2.1 设备与状态确认（来自 docs/06）

- [ ] 设备身份已确认：型号/代号 `polaris`、IMEI 后四位已记录（不记录完整 IMEI）。
- [ ] 当前系统真实状态已确认：Android / 其他系统 / iOS16 移植系统的具体表现与来源（若无法确认，必须写明"不可确认"）。
- [ ] Bootloader 可进入性、锁状态已记录。
- [ ] Recovery 可进入性、类型（Lineage Recovery / TWRP / 其他）、版本画面信息已记录。
- [ ] 活动槽位 / 分区布局 / 动态分区（super）情况已记录（只读方式）。
- [ ] 固件区域与版本基线已记录（不跨区混刷的前提）。
- [ ] Android adb/fastboot 可用性结论已记录（"可用/不可用/未知"及具体表现）。
- [ ] **回退路径草案已写出**：从当前状态恢复到"官方 LineageOS 22.2 polaris 可启动状态"的完整步骤（描述性即可）。
- [ ] 回退所需文件已获取且**校验值可查**：官方 22.2 ROM 包、对应 Recovery 镜像（以及如需要的原厂固件包）。
- [ ] 解释器/工具版本已记录（platform-tools 版本、路径）。

### 2.2 数据与安全

- [ ] 个人数据已备份，且**至少做过一次恢复验证**（备份不等于可恢复）。
- [ ] 已明确解锁/刷写会导致数据被清空的风险（官方解锁流程通常会清用户数据）。
- [ ] 已确认本次操作由设备所有者授权，并接受变砖风险。
- [ ] 设备电量 > 50%（推荐接近满电）。
- [ ] 稳定的 PC + 数据线 + USB 口（避免使用扩展坞/劣质线）。
- [ ] 已记录设备当前系统镜像/来源（如可获取），供回退参考。

### 2.3 构建产物与记录（来自 docs/05）

- [ ] 待刷写的 ROM 产物存在，且 `sha256` 已记录并与 `sha256sums.txt` 一致。
- [ ] 产物对应的构建记录（记录编号）已填写完整：源码 commit、lunch target、命令、Termux sha256 等。
- [ ] 已明确本次刷写对应的实机测试编号（T01–T15 / 扩展项）与记录方式。
- [ ] 已确认产物类型（OTA zip / 镜像）与目标设备/分区匹配（由首席在 Phase 0 核实后判定）。

### 2.4 记录与协作

- [ ] 本次真机操作已在任务板登记，且执行人=首席。
- [ ] 操作记录模板已就绪（每一步：时间、现象、截图/日志文件名）。
- [ ] 任何异常时的"停止并回退"判据已事先约定（见 §5）。

> **未勾选任何一项，都不得开始刷写。** 待补全：以上清单中涉及具体命令/路径/版本数值的部分，由首席在 Phase 0 核实后填写（只填空，不改判据）。

## 3. 数据备份要点（描述性）

- **全量备份**：照片/视频/文档/聊天记录/应用数据/浏览器书签/两步验证迁移信息等；分账户清点，避免只备份"看起来重要"的部分。
- **两份以上**：PC 一份 + 云端/第二块盘一份；关键资料加密。
- **可恢复性验证**：随机挑若干文件在另一台设备打开验证；聊天记录导出后要实际导入验证。
- **系统侧备份**：当前系统（据称 iOS16 移植）中如可导出配置/描述文件/激活信息，记录其来源与恢复方式；**不假设**其可迁移到 Android。
- **记录备份位置**：备份路径、时间、校验值（如 `sha256`）写入操作记录。
- **明确不可逆点**：Bootloader 解锁/刷写/分区改动可能导致数据不可恢复；备份必须在这些动作**之前**完成。

> 待首席在 Phase 0 核实后补全：当前系统的实际数据位置与可导出方式（取决于设备真实系统状态）。

## 4. 流程草案（阶段化，全部为描述性步骤）

> 以下每个阶段都必须"先确认前置、再执行、再记录"；任何一步异常即停止并进入 §5 排查，**不得连续尝试多个动作**。

### Phase 0：只读核验（不写入）

- 目标：确认设备真实状态、分区/固件、Recovery、回退路径（[`docs/06`](./06_Phase0_设备核验清单.md)）。
- 允许：只读查询、拍照记录、记录现象。
- 禁止：任何写入/擦除/解锁/重锁动作。
- 交付：docs/06 记录表填满；回退路径草案成形。
- **待首席在 Phase 0 核实后补全**：核验命令由首席按 docs/06 执行；本文不重复其命令。

### Phase 1：建立"可回到官方 22.2"的基线

- 目标：在动 TerminalOS 之前，先证明"设备能回到官方可启动状态"。
- 前置：Phase 0 完成；官方 22.2 ROM 与 Recovery 已获取并校验；数据已备份并验证。
- 草案顺序（描述性）：
  1. 确认设备当前可进入的引导/恢复界面；
  2. 按 LineageOS 官方 polaris 安装文档的流程恢复到官方 22.2（具体命令由首席执行并记录）；
  3. 首次启动后记录系统版本、基础硬件状态；
  4. 记录"官方 22.2 可启动"这一基线证据（对应 T15 恢复流程的第一次演练）。
- 失败即停：若无法回到官方系统，**不得**继续后续刷写。
- **待首席在 Phase 0 核实后补全**：具体恢复步骤、所需文件、分区/固件约束。

### Phase 2：刷入候选产物（未修改基线或实验版）

- 目标：刷入 docs/05 中已记录的候选 ROM，验证能否启动。
- 前置：Phase 1 基线成立；候选产物 sha256 已记录并与构建记录一致；回退方案已就绪。
- 草案顺序（描述性）：
  1. 再次核对产物类型/目标设备/校验值；
  2. 按官方安装流程刷入（命令由首席执行并记录）；
  3. 记录首次启动现象（logo、动画、是否进系统、是否进 Termux）；
  4. 若无法启动：立即按 §5 回退，不做二次尝试。
- **待首席在 Phase 0 核实后补全**：刷入方式（Recovery 侧 / 引导侧）、是否需先清数据、分区约束。

### Phase 3：实机测试（T01–T15）

- 目标：按 [`acceptance/验收测试矩阵.md`](../acceptance/验收测试矩阵.md) 逐项测试并记录。
- 前置：Phase 2 启动成功（至少进系统）。
- 规则：只由首席记录结果；每项记录 ROM 版本/时间/步骤/现象/证据；失败项附 `logcat` 关键片段与截图。
- **待首席在 Phase 0 核实后补全**：测试所需的前置操作（如解锁方式、维护入口）。

### Phase 4：回滚演练与固化

- 目标：把"回到官方 22.2"从草案变成**验证过**的流程（T15 通过），并固化到文档。
- 动作：在可接受时机做一次完整回滚演练，记录每一步耗时与问题。
- 产出：把回滚步骤从"草案"升级为"已验证流程"，并更新本文档。

## 5. 回滚到官方 LineageOS 22.2（描述性路径）

> 本节只描述**思路与检查点**，不提供命令。正式命令由首席依据官方 polaris 安装文档、在 Phase 0 核实分区/固件后执行并记录。

1. **文件准备**：从官方设备页获取 LineageOS 22.2 polaris 安装包与对应 Recovery（来源：<https://download.lineageos.org/devices/polaris>，链接与版本可能变化，执行前核对官方页面）；记录文件名与校验值。
2. **校验**：核对下载文件的官方校验值；记录到操作记录。
3. **现状确认**：确认设备当前可进入的引导界面、分区布局与原厂固件基线；确认不会跨区混刷。
4. **进入恢复环境**：由首席按 docs/06 已核实的方式进入对应 Recovery/引导界面。
5. **恢复官方系统**：按官方安装文档执行恢复（命令由首席执行，本文不写）；必要时按官方文档先清理用户数据（内容会被清空，必须已完成备份）。
6. **首次启动与验证**：确认能进入官方 22.2 系统；记录版本、基础硬件状态（对应 T15）。
7. **异常处理**：若无法进入系统或无法进入 Recovery，**停止**，进入 §6 排查顺序；在确认下一步之前不做额外写入。
8. **记录**：全过程写入 docs/05 记录与 docs/06 记录表；保留截图/日志。

**风险提示（未核实项）**：

- 当前设备据称运行 iOS16 移植系统，其引导链/分区可能已偏离官方基线，**官方 22.2 的恢复流程能否直接适用，未验证**。
- 若需要更底层恢复模式（厂商救援/EDL 类），可行性、授权与风险**未知**，必须先评估再决定；本文不提供方案。
- **待首席在 Phase 0 核实后补全**：回退所需的各界面进入方式、文件清单、分区限制、失败兜底方案。

## 6. 故障排查顺序（按"先只读、后写入"原则）

> 任何一项排查都先保持**只读**；确实需要写入时，由首席判断并记录，且先确认回退路径。

| 现象 | 排查顺序（从只读到可能写入） | 停止条件 |
| --- | --- | --- |
| PC 不识别设备 | 1) 换线/换 USB 口/换 PC；2) 检查驱动与 platform-tools 版本；3) 确认设备当前系统处于何种模式；4) 记录被识别成的设备名 | 未确认设备模式前不写入 |
| 无法进入 Bootloader/Recovery | 1) 复核按键组合与时机；2) 电量与线材；3) 记录屏幕现象；4) 参考 docs/06 的进入方式核验 | 若仍无法进入，**停止**，不盲目尝试 |
| 刷入后无法启动（卡 logo/黑屏/重启循环） | 1) 记录现象与时长；2) 确认产物与设备匹配、sha256 一致；3) 确认是否需清数据/换槽位；4) 按 §5 回退 | 回退方案就绪前不再刷入第二个镜像 |
| 能进系统但功能异常（Wi-Fi/基带/触屏/显示等） | 1) 记录具体功能与日志；2) 对比官方 22.2 基线（同硬件是否正常）；3) 判定是产物问题还是环境/固件问题；4) 停止继续刷写，先记录 | 未定位前不做回退以外的写入 |
| 数据异常/丢失 | 1) 立即停止写入；2) 从备份恢复并验证；3) 记录备份与恢复过程 | — |
| 疑似分区/固件损坏 | 1) 停止一切操作；2) 记录当前可进入的界面与报错；3) 由首席评估是否需要底层救援；4) 未评估前不动作 | 未经评估不执行任何救援写入 |

**通用原则**：每次只改变一个变量；先记录再操作；失败后先回退到已知可启动状态，再分析原因。
