# 验收测试矩阵（T01–T15 + 扩展项）

- 规则：任何涉及锁定任务、SystemUI、导航栏或启动链的修改，**必须实机测试**，不可仅凭编译通过判定完成。
- 状态：`未执行` / `通过` / `部分通过` / `失败` / `阻塞` / `后补（依赖 ROM/框架补丁）`。
- 2026-10-28 首轮真机：official LineageOS 22.2（`22.2-20261022-NIGHTLY-polaris`）+ ADB 部署，实证见 [docs/15](../docs/15_真机零构建验证记录.md) 与 [evidence/2026-10-28/](../evidence/2026-10-28/)。
- 记录要求：每个用例需记录测试 ROM 版本、时间、操作步骤、观察结果、截图/日志文件名。
- **2026-10-29 交付口径（[docs/11](../docs/11_决策记录.md) D-25，零构建先交付）**：当前交付基线是**零构建交付**（官方 22.2 镜像 + ADB 部署），整包 ROM 构建不是上线前置。**T05、T07/T08 三项标记为「后补（依赖 ROM/框架补丁）」**，需要在整包构建 + 大 runner 条件下才能验收，属后续项：**既不算失败，也不算"失败即交付不完整"，不得用这三项否掉零构建交付**。触发条件与复测口径见 §后补项触发条件与复测口径。

## 判定原则

1. 只有"实际观察到"的结果才能记为通过；模拟器、编译通过、代码推断都不算。
2. 失败项必须记录：ROM 版本、复现步骤、`logcat` 关键片段、截图。
3. 若某项因环境无法测试，记 `阻塞` 并写明原因，不得写"应该没问题"。
4. 后补项（T05/T07/T08）在零构建交付阶段只按「后补」跟踪，不计入失败/不完整判定（D-25）；触发条件满足后按原通过标准复测。
